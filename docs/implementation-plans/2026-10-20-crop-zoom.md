> **Superseded in part.** This plan built the stage model, where the
> crop rect grows over a padded stage. FDR-007 decision 1 replaced it
> with a fixed window and the image panning and zooming behind it. The
> plan is kept as a record and no longer describes the code.

> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When `<image-crop>` has a locked ratio, give it a zoom slider
(`<input type="range">`). The slider runs from "whole image visible,
padded with a fill color" to a close zoom. A square image can then
become a 1200x630 link card without losing its top and bottom.

**Architecture:** Under a locked ratio the Crop Frame shows a *stage*.
The stage is the smallest rect of the locked ratio that contains the
whole image, with the image centered in it. The crop rect may sit
anywhere on the stage, so it can extend past the image's edges, and
those regions are painted with `fill`. The slider is another way to
set the rect's size: it keeps the rect's center, just as a corner
handle drag sets the size from an anchor. Free-form cropping is
unchanged, because its stage is the image itself.

**Tech Stack:** TypeScript, `@substrate-system/web-component`, tapzero
browser tests through `tapout`, lightningcss.

**Spec:** This plan carries the decisions under Decisions below. Task 5
records them as FDR-007. The request came from rebase.blog's cover
image field, which crops to `1200/630`.

## Decisions

These were settled with the user on 2026-10-20.

1. The control is a native `<input type="range">` rendered inside
   `<image-crop>`. It is not a custom widget. Keyboard, touch and
   screen-reader support come from the platform (ADR-001).
2. The slider covers both zoom out and zoom in. `min` is 1, meaning
   the rect equals the stage and the whole image is visible. `max` is
   a close zoom, defined in Task 1. It appears only while a ratio is
   locked (`crop` is a ratio, `circle` or `constrain`). With free-form
   cropping it carries the `hidden` attribute.
3. The padding color is a new `fill` attribute on `<image-crop>`. It
   takes any CSS color the canvas `fillStyle` accepts and defaults to
   `#fff`. It is forwarded by `cropDialog({ fill })` and by a `fill`
   attribute on `<image-input>`, the same way `crop` is.
4. A rect lying entirely inside the image produces the same bytes as
   it does today, with no fill painted. Fill is painted, behind the
   whole image, only when the rect extends past the image. This keeps
   current output byte-identical for every existing consumer that
   never zooms out, including transparent PNGs.
5. The initial rect is still the cover rect (`fitRatioRect`), so
   opening the dialog looks the same as today apart from the visible
   stage padding.
6. The public `crop` getter and `image-crop:change` keep reporting
   image natural pixels. A padded rect has negative `x`/`y`, or
   extends past `naturalWidth`/`naturalHeight`. That is the documented
   meaning of padding.
7. Naming: the glossary already uses **Scale** for the ratio between
   natural and display pixels, so the control, its class and its
   helpers are called **zoom**.

### Task 1: Stage and zoom math

**Files:**
- Modify: `src/crop-math.ts`
- Test: `test/crop-math.ts`

**Interfaces:**
- Produces, all exported from `src/crop-math.ts`:
  - `containRatioRect(ratio:number, naturalWidth:number,
    naturalHeight:number):CropRect` returns the smallest rect of
    `ratio` that contains the whole image, centered, in image natural
    pixels. Its `x` or `y` is zero or negative. This is the stage.
  - `shiftRect(rect:CropRect, dx:number, dy:number):CropRect` returns
    the rect translated by `(dx, dy)` with its size unchanged.
  - `zoomRect(rect:CropRect, width:number, ratio:number,
    bounds:DisplaySize):CropRect` returns a rect of the given width and
    `width / ratio` height. It keeps the center of `rect`, then passes
    the result through `clampRect(…, bounds)`.
  - `MAX_ZOOM_PAST_COVER = 4`.
  - `zoomMax(stageWidth:number, coverWidth:number,
    minWidth:number):number` returns `Math.max(cover, Math.min(cover *
    MAX_ZOOM_PAST_COVER, stageWidth / minWidth))`, where
    `cover = stageWidth / coverWidth`. In words: the slider never stops
    short of the cover rect, and goes no further than 4x past cover or
    the minimum rect size, whichever comes first.

- [ ] **Step 1: Write the failing tests** in `test/crop-math.ts`

```ts
test('containRatioRect pads a square image at the sides', t => {
    const r = containRatioRect(1200 / 630, 100, 100)
    t.equal(r.height, 100, 'height should match the image')
    t.equal(r.width, 100 * 1200 / 630, 'width should follow the ratio')
    t.equal(r.x, -(r.width - 100) / 2, 'should center horizontally')
    t.equal(r.y, 0, 'should not pad vertically')
})

test('containRatioRect pads a wide image above and below', t => {
    const r = containRatioRect(2, 300, 100)
    t.equal(r.width, 300, 'width should match the image')
    t.equal(r.height, 150, 'height should follow the ratio')
    t.equal(r.y, -25, 'should center vertically')

test('containRatioRect equals the image when ratios match', t => {
    t.deepEqual(containRatioRect(2, 200, 100),
        { x: 0, y: 0, width: 200, height: 100 })

test('zoomRect keeps the center and the ratio', t => {
    const r = zoomRect({ x: 50, y: 25, width: 100, height: 50 }, 50, 2,
        { width: 400, height: 200 })
    t.deepEqual(r, { x: 75, y: 37.5, width: 50, height: 25 })
})

test('zoomRect clamps a grown rect into the bounds', t => {
    const r = zoomRect({ x: 0, y: 0, width: 100, height: 50 }, 200, 2,
        { width: 200, height: 100 })
    t.deepEqual(r, { x: 0, y: 0, width: 200, height: 100 })
})

test('shiftRect translates without resizing', t => {
    t.deepEqual(shiftRect({ x: 1, y: 2, width: 3, height: 4 }, -1, 5),
        { x: 0, y: 7, width: 3, height: 4 })
})

test('zoomMax caps at 4x past cover', t => {
    // stage 200 wide, cover 100 wide -> cover zoom 2; min size allows 50
    t.equal(zoomMax(200, 100, 4), 8)
})

test('zoomMax caps at the minimum rect size', t => {
    t.equal(zoomMax(200, 100, 40), 5)
})

test('zoomMax never falls below the cover zoom', t => {
    t.equal(zoomMax(200, 100, 150), 2)
})
```

### Task 2: Lay the cropper out on the stage

**Files:**
- Modify: `src/crop.ts`, `src/crop.css`
- Test: `test/crop.ts`

**Interfaces:**
- Consumes: `containRatioRect` and `shiftRect` from Task 1.
- Produces:
  - Private `#stage:CropRect`, in image natural pixels. It is the
    contain rect under a lock and `{0, 0, naturalWidth,
    naturalHeight}` otherwise. It is recomputed wherever `#ratio` is
    resolved (`#handleImageLoad`, `handleChange_crop`).
  - `#toDisplay(rect:CropRect):CropRect` and
    `#fromDisplay(rect:CropRect):CropRect` convert between image
    natural pixels and stage display pixels:
    `toDisplayRect(shiftRect(rect, -stage.x, -stage.y), scale)` and its
    inverse. Every existing `toDisplayRect`/`toNaturalRect` call in
    `crop.ts` goes through these instead.
  - `#fitted()` fits the stage, not the image, and
    `#scale() = #fitted().width / #stage.width`. Drag and keyboard
    bounds stay `#fitted()`, which now means the stage.
  - In `#layout()`, the `<img>` is positioned inside the frame at the
    image's display offset (`left`/`top` = `-stage.x * scale`,
    `-stage.y * scale`). `src/crop.css` gives `.image-crop-frame img`
    `position: absolute`. Because the frame's size is set explicitly,
    nothing else in the layout depends on the image being in flow.

### Task 3: The zoom slider

**Files:**
- Modify: `src/crop.ts`, `src/crop.css`, `src/_vars-crop.css`
- Test: `test/crop.ts`

**Interfaces:**
- Consumes: `zoomRect` and `zoomMax` from Task 1, and `#stage` and
  `#toDisplay`/`#fromDisplay` from Task 2.
- Produces markup and behavior:
  - `render()` appends this after `.image-crop-frame`:
    `<label class="image-crop-zoom"><span>Zoom</span><input
    type="range" min="1" step="any"></label>`. The label carries
    `hidden` while `#ratio` is null. `#layout()` toggles it.
  - `#layout()` sets the input's `max` to
    `zoomMax(stage.width, cover.width, minWidth)` and its `value` to
    `stage.width / #crop.width`. Here `cover` is
    `fitRatioRect(#ratio, …)` and
    `minWidth = Math.max(MIN_DISPLAY_SIZE,
    MIN_DISPLAY_SIZE * #ratio) / #scale()`. Every rect change (drag,
    key, slider, load, resize) passes through `#layout()`, so this one
    place keeps the slider in sync.
  - An `input` listener (added in `connectedCallback`, removed in
    `disconnectedCallback`) computes
    `#crop = #fromDisplay(zoomRect(#toDisplay(#crop),
    displayStageWidth / value, #ratio, #fitted()))`, then calls
    `#layout()` and emits `change` with the natural rect, like the
    other mutation paths.
  - CSS: `.image-crop-zoom` is a flex row with a gap, its input is
    `flex: 1`, and it uses `font-size: 1rem` or larger. Color the input
    with `accent-color: var(--image-crop-zoom-accent)`, a new variable
    in `src/_vars-crop.css` that defaults to the existing handle border
    blue.

### Task 4: Fill the padding in the output, and forward `fill`

**Files:**
- Modify: `src/crop.ts`, `src/crop-dialog.ts`, `src/index.ts`
- Test: `test/crop.ts`, `test/crop-dialog.ts`, `test/index.ts`,
  `test/helpers.ts`

**Interfaces:**
- Consumes: the slider from Task 3, which the tests use to zoom out.
- Produces:
  - `ImageCrop`: `fill` is added to `reflectedStringAttributes`
    (`declare fill:string|null`) and `DEFAULT_FILL = '#fff'` is
    exported. `#layout()` sets the frame's `backgroundColor` to
    `this.fill ?? DEFAULT_FILL`, so the padding on screen matches the
    output. `handleChange_fill` calls `#layout()`.
  - `getBlob()`: when the rect lies inside `[0, naturalWidth] x
    [0, naturalHeight]`, the draw is the existing one, unchanged.
    Otherwise it paints `fillRect(0, 0, width, height)` with the fill
    color, then `drawImage(img, -x, -y)`.
  - `CropDialogOptions.fill?:string`, forwarded with
    `crop.setAttribute('fill', …)` next to `crossorigin`.
  - `ImageInput`: `fill` is added to `reflectedStringAttributes` and
    forwarded to its `<image-crop>` in `edit()` beside `crop`, with
    the same set-or-remove shape.
  - `test/helpers.ts`:
    `pixelAt(blob:Blob, x:number, y:number):Promise<number[]>` returns
    RGBA through `createImageBitmap` and `getImageData`, and
    `makeTransparentFile(width:number, height:number):Promise<File>`
    returns a fully transparent PNG.
